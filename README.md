# Credit_prediction_case

Predicting whether a client will submit a credit application in a future month (t+1 and t+3 horizons), based on monthly transaction and balance data.

## Repository structure

```
Credit_prediction_case/
├── data/
│   ├── credit_applications.csv        # raw: monthly credit application records
│   ├── customers.csv                  # raw: monthly transaction/balance data
│   └── processed/                     # generated by data_preprocessing.ipynb
│       ├── xgboost_t1/                # train.parquet, val.parquet, test.parquet
│       ├── xgboost_t3/
│       ├── log_reg_t1/
│       └── log_reg_t3/
├── models/
│   ├── train_xgboost.py               # XGBoost training, tuning, evaluation, saving
│   ├── train_logistic_regression.py   # Logistic regression equivalent
│   ├── compare_models.py              # Test-set comparison of saved models
│   ├── explain_models.py              # SHAP explainability
│   └── artifacts/                     # generated: saved models + chosen thresholds
├── notebooks/
│   ├── t1/                            # next-month prediction horizon
│   │   ├── train_xgboost_t1.ipynb
│   │   ├── train_logreg_t1.ipynb
│   │   └── compare_models_t1.ipynb
│   └── t3/                            # three-months-ahead prediction horizon
│       ├── train_xgboost_t3.ipynb
│       ├── train_logreg_t3.ipynb
│       └── compare_models_t3.ipynb
├── eda_credit_applications.ipynb      # Exploratory data analysis
└── data_preprocessing.ipynb           # Cleaning, feature engineering, splits
```

The training and comparison modules are horizon-agnostic: each notebook calls `set_horizon("t1")` or `set_horizon("t3")` to point the module at the right dataset and target column.

## What to run

Run the notebooks in this order — each step depends on the outputs of the previous one.

### 1. Explore the data (optional)

`eda_credit_applications.ipynb` — understand distributions, missingness, and the target base rate.

### 2. Preprocess and build datasets

`data_preprocessing.ipynb`

Merges the raw datasets, imputes genuine data gaps, engineers features, and writes four model-ready datasets split into train/validation/test:

| Split | Period |
|---|---|
| train | `yearmonth <= 2015-08` |
| validation | `2015-09 <= yearmonth <= 2015-12` |
| test | `yearmonth >= 2016-01` (imputed rows excluded) |

**Output:** `data/processed/{dataset}/{split}.parquet`

### 3. Train the models

Pick a horizon folder (`notebooks/t1/` for next-month, `notebooks/t3/` for three-months-ahead) and run both training notebooks:

- `train_xgboost_{t1,t3}.ipynb`
- `train_logreg_{t1,t3}.ipynb`

Each notebook:
1. Tunes hyperparameters with Optuna, maximizing PR-AUC on the **validation** split.
2. Plots the validation precision-recall curve so you can **manually pick a threshold** matching the business objective — set `SELECTED_THRESHOLD` in the notebook.
3. Evaluates on train/validation/test at that threshold.
4. Saves the model, feature list, and threshold.

**Output:** `models/artifacts/{xgboost,log_reg}_{t1,t3}.joblib`

> The threshold is deliberately not tuned automatically — re-run the final cells after adjusting `SELECTED_THRESHOLD`.

### 4. Compare and explain

`notebooks/{t1,t3}/compare_models_{t1,t3}.ipynb` — requires both artifacts for that horizon from step 3.

- Test-set metrics per model, with precision/recall averaged **per month**.
- Per-month breakdown to check stability over time.
- Overlaid precision-recall curves and lift over the random baseline.
- SHAP feature importance, direction of effect, cross-model agreement, and single-prediction explanations.

## Running scripts directly

The training modules can also be run from the command line (using a default threshold of 0.5):

```bash
python models/train_xgboost.py
python models/train_logistic_regression.py
```
